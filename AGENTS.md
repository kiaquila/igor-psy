# igor-psy

Статический сайт частной практики. Страницы и ресурсы находятся в `public/`, маршруты Cloudflare Workers заданы в `wrangler.json`. Команды проверки и порядок работы с PR описаны в [README.md](README.md) и [инструкции по разработке](docs/development.md).

## Работа с агентами

- Координатор формулирует критерии приёмки, назначает владельца каждому набору файлов, интегрирует изменения и отвечает за итоговый PR.
- `site_implementer` меняет назначенные файлы. Параллельные правки распределяйте по непересекающимся путям. Для независимых изменений используйте отдельные worktree в `worktrees/<slug>`. Общий файл меняет один агент за раз.
- `site_qa` и `site_reviewer` проверяют собранный diff. QA воспроизводит пользовательские сценарии и запускает preflight. Ревьюер сообщает конкретные регрессии с приоритетом, файлом и строкой. Оба возвращают вывод координатору и оставляют правки исполнителю.
- Перед PR запустите `sh scripts/preflight.sh`. Для изменений интерфейса проверьте затронутые страницы на мобильной и широкой ширине, переходы с клавиатуры и открытие записи в Telegram без отправки сообщения.
- После последнего push запросите Codex Review для полного SHA и дождитесь двух зелёных проверок, `Preflight` и `Codex Review`. После исправлений повторите проверку на новом SHA.

## Code Review Rules

- Проверяйте путь до записи со страниц `/`, `/practice/` и `/404.html`. Ссылка должна открывать `@CherkasovPsy` с готовым сообщением. Потеря адресата, текста или возможности дойти до ссылки с клавиатуры ломает запись.
- Сохраняйте прямые переходы на `/practice/` и его якоря, а также поведение 404 в Cloudflare. При изменениях разметки проверяйте, что навигация и FAQ работают с клавиатуры.
- Отмечайте ослабление gate, если можно принять отзыв стороннего автора, отзыв на другой SHA или выполнить код из PR в workflow с правом записи GitHub Checks.
